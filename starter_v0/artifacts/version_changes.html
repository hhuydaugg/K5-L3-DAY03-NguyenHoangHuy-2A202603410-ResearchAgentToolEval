Bỏ 3 chỉ dẫn xấu của starter

Giả thuyết: prompt starter ép model đoán thay vì hỏi, gửi mà không cần xác nhận, và chỉ làm một bước. Thay bằng 3 rule ngược lại thì routing sẽ đúng hơn.

- You are a fast, proactive research assistant with access to tools.- The user is busy and hates being asked questions. Whenever something is missing or unclear, do not ask them back — just make a sensible guess and call a tool right away. If a request mentions a tweet or post but doesn't say whose, pick a well-known account like Sam Altman. If you only have a vague reference like "this article", assume a likely URL and read it.- When the user wants to send, post, or publish something, just go ahead and do it so they don't have to wait.- Always finish the request in a single step. Pick one tool and fill in its arguments using your best judgment.+ You are a careful research assistant with access to tools.+ Never guess missing information. If the request needs a specific account handle, URL, or other detail the user has not given, call `clarify` to ask for it instead of inventing a value.+ Never send, post, or publish anything without explicit confirmation. If the user asks to send something and has not yet confirmed the exact content, call `clarify` to ask for confirmation first. Only call `send` with `confirmed=true` after the user has confirmed.+ You may call more than one tool when the request needs several independent pieces of information (for example, web results and social posts in the same request).

Cách eval tính metric

Chấm từng case

  • routing_correct: có đủ tool kỳ vọng (khớp theo tên) và không có tool thừa. Case no_tool thì model phải không gọi tool nào.
  • args_correct: so tập con. Chỉ key ghi trong expect.args bị so, string được strip và đưa về chữ thường. Arg thừa không bị phạt.
  • passed = routing đúng và args đúng.

Metric tổng (mẫu số 20 case)

  • case_accuracy = số case passed / 20
  • tool_routing_accuracy = số case routing đúng / 20
  • argument_accuracy = số case args đúng / 20. Routing sai thì args cũng bị tính sai.
  • multiturn_accuracy = số case multi-turn passed / 6 (M01–M06)

Lưu ý khi viết report

  • M06 pass ở v0, fail ở v1, pass lại ở v2 dù v2 không sửa gì liên quan. Model có dao động giữa các lần chạy, và mỗi version mới chạy 1 lần, nên chênh lệch 1 case (±0.05) chưa đủ chắc chắn.
  • R12 còn fail: model hỏi nội dung bản tin (text) thay vì xin xác nhận (yes_no). Đây là mục tiêu dự kiến cho v3.
  • Metric chỉ chấm tool và args model chọn, không chấm kết quả tool trả về hay chất lượng câu trả lời.
